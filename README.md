# DermEMR — онлайн медицинская карта приема дерматолога

Рабочее место врача-дерматовенеролога с сервером, кассой, генерацией PDF и отправкой документов пациенту.
Реализовано по документам `prd.md`, `technical_specification_spec.md`, `design_system_ui_ux_specification.md`.

## Как запустить на компьютере

1. Установите **Node.js LTS** (версия 18.17 или новее): https://nodejs.org. Достаточно сделать это один раз.
2. Дважды щелкните **`start.bat`** (на macOS / Linux — `./start.sh`).
   - При первом запуске устанавливаются зависимости: нужен интернет, это занимает 1–3 минуты.
   - Затем приложение собирается и запускается сервер.
3. Браузер откроется сам на **http://localhost:3000**. Если не открылся, введите адрес вручную.

Окно с сервером не закрывайте, пока работаете. Чтобы остановить сервер, закройте окно или нажмите `Ctrl+C`.

То же самое из терминала: `npm install`, затем `npm run build`, затем `npm start`.

## Что внутри

| Адрес | Экран |
| --- | --- |
| `http://localhost:3000/#/` | **Очередь приема**: демо-пациенты, кнопка «Новый пациент», переход в карту |
| `#/encounter/<id>` | **Карта приема по страницам**: Жалобы → Осмотр → Диагноз → Лечение → Итог. Кнопка «Одним листом» включает прежнюю сетку 20/60/20 |
| `#/day-hospital` | **Дневной стационар**: курсы по 10 дней, перевод пациента из приёма одним нажатием |
| `#/day-hospital/<id>/print/ru` · `/uz` | **Лист назначений** для печати (A4, альбомная) на русском или узбекском |
| `#/cashier` | **Касса**: счета приходят от врача в реальном времени, кнопка «Принять оплату» |
| `#/portal/<patientId>` | **Личный кабинет пациента**: опубликованные PDF и назначения |
| `/m/upload?t=…` | **Страница для смартфона**: открывается по QR, снимок уходит прямо в карту |
| `/verify/<код>` | **Проверка подлинности документа**: на эту страницу ведет QR-код в PDF |

### Демо-пациенты
- **Морозова А. В.** — псориаз, повторный прием с заполненным протоколом. У нее аллергия на лидокаин и пенициллины, есть история визитов и анализов, снимки «До / После».
- **Ковалев Д. С.** — первичный прием, пустая карта.
- **Юсупова М. Р.** — беременность, ИДС не подписано. На ней видно работу CDSS: шаблон «Акне» блокируется из-за адапалена, изотретиноин тоже. Отправка в мессенджеры заблокирована до подписания согласия.

Вернуть демо-данные к исходному состоянию: `npm run reset-demo`. Команда удаляет папку `storage/`.

### Загрузка фото со смартфона
Кнопка **QR** в блоке «До / После» показывает код. Смартфон должен быть в той же Wi-Fi сети, что и компьютер.
При первом запуске Windows может спросить разрешение для Node.js в брандмауэре: разрешите доступ в частных сетях.
Если QR-код ведет на неверный адрес, укажите его вручную в `.env`, например `PUBLIC_URL=http://192.168.1.10:3000`.

### PDF
Сервер формирует PDF через установленный **Microsoft Edge** (есть в Windows 10/11) или **Google Chrome**. Отдельно ничего скачивать не нужно.
- Формат A4: швейцарская верстка, QR-код проверки подлинности, отдельные листы рецептов 107-1/у и экстемпоральных прописей, памятка, смета.
- Мобильная версия: ширина 390pt, динамическая высота, одна страница.

Если браузер не найден, пропишите путь в `PDF_BROWSER_PATH`. Без браузера документы выдаются в HTML для печати.

### Клинические протоколы МЗ РУз
Когда врач выбирает диагноз, под блоком «A» появляется панель «Протокол МЗ РУз». В ней:
- препараты из стандарта по нозологии: наружная и системная терапия, процедуры, а также обследования; у каждого препарата указаны способ применения, суточная и курсовая доза;
- метки «доп.» (раздел «Дополнительные лечебные мероприятия») и «спец. уровень» (в стандарте не отмечено для первичного звена);
- кнопка «В назначения» добавляет препарат в план с кратностью и длительностью из стандарта и сразу проверяет его на аллергии, беременность и взаимодействия;
- предупреждение, если в плане есть препарат, которого нет в стандарте по этой нозологии;
- ссылки на PDF клинического протокола (сразу на разделе «Лечение») и стандарта.

Сейчас загружено 32 нозологии. Справочник `src/data/guidelines.json` собран автоматически из таблиц стандартов в папке `guidelines/`. Сервер раздает эти PDF по адресу `/guidelines/<файл>`. Дозы перед назначением сверяйте с первоисточником.

Пересборка после обновления PDF: `pip install pdfplumber`, затем `python scripts/guidelines/run.py`, затем `npm run build`. Новая нозология добавляется в список `N` в `scripts/guidelines/build_data.py`.

### Дневной стационар
Раздел работает отдельно от приёма. Курс можно оформить для нового пациента (кнопка «Новый пациент») или перевести пациента из приёма: кнопка «Оформить курс» на шаге «Итог» или в списке сегодняшних приёмов. Во втором случае ФИО, год рождения, телефон и диагноз переходят из визита, а шаблон подбирается по МКБ-10: L80 — витилиго, L70 — акне.
- Курс длится 10 рабочих дней, воскресенья пропускаются. Даты считаются от дня начала.
- Назначения можно править: название, схема (ежедневно, через день, дома по схеме, вручную), отметки по дням. Нажатие на клетку меняет её по кругу: пусто → «+» → «−» → пусто.
- Цвета клеток: «+» светло-зелёный, «−» (пропуск через день) светло-розовый, пусто (дома по схеме) жёлтый. Доза пишется числом.
- Для изотретиноина (Изона, Роаккутан, Акнекутан) под строкой выводится предупреждение о беременности и печёночных пробах — и в программе, и на листе.
- Интерфейс курса и лист назначений переключаются между русским и узбекским (кириллица).

Без сервера курсы хранятся в браузере.

### Мессенджеры
Пока токены в `.env` пусты, Telegram, WhatsApp и MAX работают в **демо-режиме**: статусы «Отправлено → Доставлено → Прочитано» симулируются. Личный кабинет работает всегда. Как подключить настоящие каналы:

- **Telegram:** токен от @BotFather → `TELEGRAM_BOT_TOKEN`.
  - Бот работает через long polling, поэтому публичный адрес не нужен.
  - Если пациент еще не писал боту, врач получает ссылку `t.me/<бот>?start=doc_…`. Когда пациент открывает ее, документы приходят автоматически.
- **WhatsApp Business Cloud API:** нужны `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID` и одобренный шаблон с заголовком-документом.
  - Статусы «доставлено / прочитано» приходят на `/webhooks/whatsapp`, а для этого нужен публичный HTTPS-адрес сервера.
- **MAX:** токен бота с business.max.ru → `MAX_BOT_TOKEN`.
  - Привязка пациента такая же, как в Telegram: по ссылке `max.ru/<бот>?start=doc_…`.

## Реализовано по этапам дорожной карты PRD

**Этап 1 (MVP)**
- Сетка 20/60/20 на 1366–2560 px.
- Протокол SOAP, 48 шаблонов по 8 группам, 22 `/макроса`.
- 2D Body Map: 4 проекции, ~70 зон, автоподстановка в локализацию.
- Корзина с двусторонней синхронизацией с разделом P и передачей на кассу. Изменения после отправки приходят кассиру отдельным событием.
- PDF A4 и Mobile, отправка в ЛК и Telegram.

**Этап 2**
- WhatsApp и MAX.
- Калькуляторы PASI, SCORAD, EASI, GAGS, DLQI, UAS7.
- Загрузка фото со смартфона по QR: метаданные удаляются на телефоне и на сервере.
- Сравнение «До / После».
- Экстемпоральные прописи (6 шаблонов, отдельный рецептурный бланк).

**Этап 3**
- CDSS: аллергия по МНН и фармгруппе, тератогены при беременности, межлекарственные взаимодействия (ретиноиды + тетрациклины, метотрексат и др.). Проверяются и ручные назначения, и препараты из шаблонов.
- Кумулятивная доза изотретиноина с учетом прошлых визитов.
- Голосовой ввод через «Диктовку» (Chrome / Edge, ru-RU).

**Сквозное**
- Автосохранение каждые 2 с с проверкой версий: при правке из второй вкладки показывается конфликт.
- Офлайн-буфер в IndexedDB и восстановление черновика.
- Подписанные ссылки на медиа и PDF живут 15 минут.
- Неизменяемый журнал аудита `storage/audit.log`: открытие карты, скачивание, отправка, оплата.
- Видеоконсультация: кнопка «Видео» открывает комнату Jitsi Meet для этого визита.

## Структура

```
start.bat / start.sh       запуск одним щелчком
.env.example               настройки (порт, PDF, токены мессенджеров)
src/                       фронтенд (React 19 + TypeScript)
  pages/                   очередь, касса, личный кабинет
  components/              шапка, левая/центральная/правая колонки, PDF-шаблоны
  lib/                     API-клиент, WebSocket, калькуляторы, CDSS, QR-кодер
  data/                    встроенные справочники (МКБ-10, прайс, препараты, шаблоны)
server/src/                сервер (Node.js): API SPEC §3, WebSocket, PDF, шлюзы мессенджеров
server/db/schema.sql       схема PostgreSQL для продакшена (SPEC §2.1)
server/seed/               демо-снимки
storage/                   данные локальной установки (создается при запуске)
```

## Разработка

```bash
npm run dev        # API с перезапуском + Vite с горячей перезагрузкой: http://localhost:5173
npm test           # тесты калькуляторов, CDSS, взаимодействий
npm run typecheck
```

Справочники редактируются в `storage/db.json`, раздел `dictionaries`. Сервер отдает их фронтенду при запуске.
Реквизиты клиники и врача заданы в `src/components/documents/Documents.tsx` (константа `CLINIC`).

## Ограничения локальной версии

- **Хранилище:** встроенное JSON-хранилище, рассчитанное на один компьютер клиники. Для сетевой установки предназначена схема PostgreSQL в `server/db/schema.sql`.
- **Пользователи:** вход и роли не реализованы. Все действия записываются в журнал от имени демо-врача.
- **PDF:** Chromium выдает обычный PDF. Строгое соответствие PDF/A-1b и подпись УКЭП требуют отдельного криптосервиса; в документе стоит штамп-заглушка.
- **Голосовой ввод:** диктовка вставляет текст в активное поле. Автоматическая раскладка по разделам SOAP требует языковой модели и не входит в эту версию.
- **Мессенджеры:** запросы к WhatsApp и MAX написаны по их публичной документации. На реальных аккаунтах они не проверялись: перед боевым запуском проверьте их с тестовыми номерами.
